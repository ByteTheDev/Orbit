# Orbit — agent map

Orbit is a Wails v2 desktop app: a Go backend plus a React/TypeScript frontend. It orchestrates coding agents (Claude Code and Codex CLI) per project. In the UI, each project is a "sun" in a galaxy and each agent is a "planet" orbiting it. Read this file first, then open only the files you need.

## Where things live

| Path | What it is |
|---|---|
| `main.go` | Wails entrypoint. Embeds `frontend/dist`, sets window options, binds `App`. |
| `app.go` | `App` struct: every method the frontend can call (`GetSnapshot`, `LaunchAgent`, `SendMessage`, `GetFileDiff`, terminal ops, icons). Also the save debounce and event emitting. |
| `internal/agent/manager.go` | Owns all projects and agents, runs turns, batches events. The largest and most central Go file (~970 lines). Search it, don't read it whole. |
| `internal/agent/icon.go` | Project icon storage (PNG decode and validation). |
| `internal/model/model.go` | Shared data types and caps. The JSON shape here is mirrored in `frontend/src/types.ts`. |
| `internal/provider/` | One adapter per CLI. `claude.go` (Claude Code, stream-json), `codex.go` (Codex, exec mode). `provider.go` defines the `Provider` interface and normalised `UpdateKind`s. `exec.go` finds CLI binaries on PATH. `models.go` holds hard-coded model lists. |
| `internal/store/store.go` | Persists state as one versioned JSON file (`store.DefaultPath`). |
| `internal/conflict/` | Detects files written by two or more agents in one project. |
| `internal/browser/` | Fetches web pages (text, title, links) for the built-in browser and for agents. `mcp.go` is the `browse_page` tool; `main.go` serves it when run with `--browser-mcp`. Providers register it per turn (`BrowserCommand` in `provider.Spec`). |
| `internal/webpane/` | Native page view for the browser dialog. On Windows, a WebView2 (Chromium) control in a child window over the dialog's viewport, on its own thread. `pane_other.go` is the non-Windows stub. Page state reaches the UI as `browser:pane` events. |
| `frontend/src/components/browser/` | The built-in browser dialog: tab strip, toolbar, and the native viewport (or the text view as fallback). Pure helpers are in `lib/browserNav.ts` (history) and `lib/browserPane.ts` (viewport bounds, address parts, landings). |
| `internal/gitdiff/` | Git operations on a project's repo: the file inspector's diff (`gitdiff.go`), and status, per-file diffs, log, stage, unstage and commit (`repo.go`) for the Changes tab and auto-commit. Windows-specific hiding in `hide_windows.go`. |
| `internal/terminal/terminal.go` | PTY shells (ConPTY on Windows) started in a project's repo. |
| `frontend/src/App.tsx` | Root layout, keyboard handling, wiring of panels and dialogs. |
| `frontend/src/lib/store.ts` | External store with selector subscriptions (`useSyncExternalStore`). Components read slices from here. Events from Go are applied here. |
| `frontend/src/lib/bridge.ts` | The only place that calls Go bindings. Errors when not running inside Wails. |
| `frontend/src/lib/actions.ts` | User actions. Each calls the backend, reports failures as toasts. |
| `frontend/src/lib/shortcuts.ts` | Keyboard map (shown in Settings › Keyboard). |
| `frontend/src/lib/theme.ts`, `index.css` | Colours. `index.css`'s `@theme` block is the source of truth. |
| `frontend/src/lib/projectIdentity.ts` | Project accent colour and symbol, derived from the id. |
| `frontend/src/lib/universe/` | Galaxy view, pure where possible: `layout.ts` (positions), `camera.ts` (zoom/pan math), `render.ts` (canvas drawing and hit-testing), `galaxyGL.ts` (WebGL nebula and stars), `galaxyShape.ts`, `galaxyArt.ts`. |
| `frontend/src/components/universe/Universe.tsx` | React wrapper that mounts the galaxy canvas. |
| `frontend/src/components/inspector/` | Agent inspector tabs (overview, chat, activity, files, tools, issues). `Inspector.tsx` is the switch. |
| `frontend/src/components/navigation/` | Project sidebar. `agentStatus.ts` is pure status grouping. |
| `frontend/src/components/dialogs/Dialogs.tsx` | All modal dialogs, selected by the store's `Dialog` union. |
| `frontend/src/components/terminal/TerminalPanel.tsx` | xterm.js panel bound to Go terminals. |
| `frontend/src/components/ui/` | Shared UI primitives and icons. |
| `frontend/wailsjs/` | **Generated by Wails. Do not edit.** |
| `frontend/dist/`, `build/bin/`, `node_modules/` | Build output and dependencies. Ignore. |

## Backend ↔ frontend contract

- The frontend calls Go through `frontend/src/lib/bridge.ts`, which uses the generated `frontend/wailsjs/go/main/App.js`.
- Go pushes updates on one event channel, `orbit:events`. Terminals use `terminal:output` and `terminal:exit`. Manager events are batched and flushed at most every `flushDelay`.
- When you change an exported `App` method or a type in `internal/model`, do both:
  1. Regenerate the bindings (`wails dev` or `wails build` rewrites `frontend/wailsjs/`).
  2. Update the mirror in `frontend/src/types.ts`.
- Empty collections must serialise as `[]`, not `null`. The manager tests check this.

## Commands

Run from the repo root unless noted.

- App, dev with hot reload: `wails dev` (or `npm run dev` at root)
- App, production build: `wails build`
- Go tests: `go test ./...` (use `-short` to skip the ConPTY shell test in `internal/terminal`)
- Frontend tests: `cd frontend && npm test` (vitest)
- Frontend typecheck: `cd frontend && npm run typecheck`
- Frontend production build: `cd frontend && npm run build`

Tests sit next to the code (`*_test.go`, `*.test.ts`) or in `frontend/src/lib/__tests__/`.

## Conventions

- Keep the pure logic in `lib/` and `internal/` free of React and Wails so it can be unit-tested. Components stay thin.
- Components read the store through selectors. Don't subscribe to the whole store.
- User-facing failures go through toasts (`actions.ts`), not thrown into components.
- Keep the Windows-only code in `*_windows.go` and `procattr_*.go` split files. Keep `*_other.go` as the fallback.
- Keep the provider adapters thin: they translate CLI output into `UpdateKind`s and nothing else.

## Working tree notes

- The working tree may contain uncommitted work from the user. Don't revert or overwrite changes you didn't make.
- `website/` is an empty folder.
- `frontend/package.json.md5` is a checksum file. Its purpose is not documented here, so leave it alone unless the task is about it.
